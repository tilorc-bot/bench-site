/-
  assume-eval: core semantics (hand-written; the only hand Lean besides primitives).

  Every expression of the benchmark format denotes a complex number (or a Prop),
  built from the operations below.  Mathlib totalises partial functions with junk
  values (Complex.log 0 = 0, a / 0 = 0, Real.sqrt (-1) = 0, ...).  These junk
  values must never leak into the meaning of a case, so:

    * we work over ℂ throughout (no Real.sqrt / Real.log);
    * every expression e comes with a definedness predicate D(e), generated
      alongside each library function (`AE.f.D`, see spec/generated/), and every
      case statement assumes / proves definedness explicitly;
    * the partial core operations and their definedness conditions are:
        inv a      defined iff a ≠ 0
        log a      defined iff a ≠ 0      (principal branch, Im ∈ (-π, π])
        floor a    defined iff a is real
        lt/le/...  defined iff both sides are real
        piecewise  defined iff some branch condition holds (else-branch optional)

  Imports.  This module is the one place that imports Mathlib; everything else (the
  generated module, spec/lemmas/, case-proof files, --lean-lib modules) gets Mathlib
  through `import core`.  Not `import Mathlib` as a whole: every Lean process loads
  the environment of its imports first, and all of Mathlib takes 15-60 s and several
  GB per process, this subset about 2 s.  The list is
    * the modules `#min_imports` reports for the spec, spec/lemmas/, the demo proofs
      and the simplipy-cases proofs and lemma modules when they import all of
      Mathlib (including instances and simp lemmas that the proofs use without
      naming them: real/star order, C*-algebra classes, pi bounds, ...);
    * the spec's vocabulary and the usual proof tactics, listed explicitly so that new
      case proofs find them (most are already imported by the first group).
  A proof that needs more Mathlib adds the module here (or, for an external case
  set, imports it in its own --lean-lib module).
-/
